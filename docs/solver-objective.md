# ソルバー目的関数と割当の採点

`T.solve` の `objective`（保存データでは `result.objective`）は HiGHS が返した整数解の目的関数値に LP の定数項を足した値です。割当だけから再計算した減点と必ず一致する値ではありません。

## 時間切れの整数解

多くの減点は、補助変数に下限を置き、それを最小化する形で表しています。時間切れで返る整数解には、必要量より大きな補助変数が残ることがあります。その場合、勤務・OC の割当が同じでも、ソルバー目的関数は割当の減点より大きくなります。これは割当の必須条件違反を意味しません。反対に、減点を再計算できたことだけでは必須条件を満たす証明にもなりません。必須条件は `T.check` で独立に検算します。

実際の HiGHS 1.15.2 の時間切れ解を同梱の架空データで保存した回帰試験では、目的関数 3945 に対して割当の減点は 1280 でした。同じ割当を全枠固定し、補助変数を最適まで解くと目的関数も 1280 になります。差は勤務目標からのずれ、短い連勤、2 連休の不足の補助変数に残った余裕です。

`status` は元のソルバー状態を保ちます。採点が小さくなっても `Time limit reached` を `Optimal` に変更しません。`gap` は HiGHS に指定した許容相対ギャップで、終了時に実測したギャップや下界ではありません。許容ギャップが正なら `Optimal` もその許容範囲での終了です。

## 採点を比較する場合

`T.penalty(P, asg, opts)` は割当から独立に減点を計算します。必ず計算時と同じ `P` と文脈を使います。

- 参照解: `ignoreAvoid: true`
- 参照解後の本計算: 同じ `avoidRef`（保存時は `result.avoid_ref`）
- 最小変更: 同じ `base` と計算時の `base_change` 重み。JS の変更項は不変部分を負として数えるので、合計が負になることがあります。
- 診断の `relax` と試験用 `jitter` は独立採点の対象文脈ではありません。元の規則での減点を、その変更済み目的関数と等しいものとして扱わないでください。

現行の本体には、複数の解を `objective` で順位付けする処理や、再計算減点による早期停止はありません。参照解方式は割当から勤務回数を取り出し、目的関数の大小では選別しません。結果画面と説明資料は目的関数を減点合計として表示しません。保存形式と数値の意味を変更せず、不要な採点フックの実行も追加していません。

## 独立実装の回帰試験

時間切れ解の生の目的関数と再計算減点が等しい、という assertion は不適切です。割当を全枠固定し、許容ギャップ 0 で `Optimal` まで解いた目的関数と独立採点を比較します。再計算値を `objective` に代入して一致させることはしません。これにより数理モデルと採点の本当の不一致を検出し続けます。

`test_timeout_objective_node.js` は実際の時間切れ解について全 LP 制約・整数領域・生の目的関数を確認し、同じ割当の固定採点と比較します。同期・Worker 相当、整数解なし、小数目標、参照解・基準回数、最小変更、診断・試験用目的関数も確認します。

Python の `build_and_solve` が返し、CLI や Markdown の「目的関数値」として表示する値も CP-SAT の生の目的関数です。`FEASIBLE` の補助変数に同様の余裕がある可能性があります。`score` コマンドは割当を固定して採点し、`OPTIMAL` 以外では失敗として扱います。JS/Python の最小変更項には定数項の規約の差があるので、そのオフセットを無視して両者の合計を直接比較しないでください。
